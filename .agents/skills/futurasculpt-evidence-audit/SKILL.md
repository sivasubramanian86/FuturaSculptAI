# FuturaSculptAI Evidence Audit Skill

## Purpose
Enforces the Zero-Fabrication Contract. Verifies that every external claim generated by agents or presented in the UI traces back to a cryptographically validated `evidence_id` in the Evidence Ledger.

## Tool Declarations & Input Schemas

```python
from pydantic import BaseModel, Field
from typing import List, Optional

class EvidenceAuditInput(BaseModel):
    """Input contract for evidence audit verification."""
    tenant_id: str = Field(..., min_length=1, description="Target enterprise tenant scope.")
    evidence_ids: List[str] = Field(default_factory=list, description="Specific evidence IDs to audit.")
    require_sha256_match: bool = Field(default=True, description="Enforce strict SHA-256 integrity match.")
    idempotency_key: str = Field(..., min_length=16, description="Cryptographic run idempotency token.")

class EvidenceAuditOutput(BaseModel):
    """Output scorecard for evidence audit."""
    total_records_scanned: int = Field(ge=0)
    cryptographic_matches_pct: float = Field(default=100.0, ge=0.0, le=100.0)
    unbacked_claims_count: int = Field(default=0, ge=0)
    evidence_gate_passed: bool
    stale_records: List[str] = Field(default_factory=list)
```

## Deterministic Credential Isolation (Zero-Trust to Model)
- **Zero-Trust Model:** The model processes content abstractions and claim entailment, never inspecting cloud storage IAM keys, service account JSON files, or database credentials.
- **Broker Resolution:** All SHA-256 validation occurs directly in native Python using in-memory byte buffers.

## Execution Sandboxing & Idempotency
- **Idempotency Guarantee:** Verification calls take an `idempotency_key` and produce deterministic verification receipts.
- **Compensating Action / Saga Readiness:** Verification is strictly read-only against the Evidence Ledger and introduces zero state mutations.

## Audit Procedure
1. **EvidenceEnvelope Schema Validation:**
   - Verify every evidence record contains `evidence_id`, `tenant_id`, `sha256_hash`, `source_uri`, `content`, `provenance`, and `acl`.
2. **Claim-to-Evidence Entailment Check:**
   - Scan generated scenario outputs and Opportunity Forge blueprints to confirm that 100% of factual assertions include citation markers referencing active evidence IDs.
3. **Freshness & Provenance Verification:**
   - Verify that evidence records do not exceed their `freshness_horizon_days` without explicit staleness warnings.

## Verification Script (PowerShell)
```powershell
# Assert all sample evidence files have matching sha256 checksums
Get-ChildItem -Path "data/sample_evidence" -Recurse -File | ForEach-Object {
    $hash = (Get-FileHash $_.FullName -Algorithm SHA256).Hash.ToLower()
    Write-Output "$($_.Name) -> $hash"
}
```

## Expected Output
Audit scorecard showing:
- Evidence coverage percentage (must be >= 95%).
- Unbacked claims or dangling citations (must be 0).
